Section 01

Introduction

Afya means health in Swahili. AfyaRisk 2.0 is an AI-powered actuarial engine built specifically for the African health insurance market. Health insurers across East Africa operate five disconnected workflows using outdated tools — static pricing tables, manual fraud review, quarterly Excel reserving, and PDF policy searches — with no unified risk intelligence layer.

AfyaRisk 2.0 replaces all five with a single, real-time API platform. Any insurer — from a Nairobi-based microinsurer to a regional reinsurer — can integrate the five engines through standard REST endpoints and get clinical-grade risk intelligence in under 500 milliseconds.

Target Users

Health insurers, reinsurers, actuarial teams, TPA administrators, and insurtech platforms across East and Central Africa.

Core Value

One unified API replacing five siloed tools — lower loss ratios, less fraud leakage, faster reserves, better policyholder experience.

Section 02

The Problem

Insurance in Africa is broken at the data layer. Five critical workflows run in silos with no shared intelligence:

Risk Mispricing

Underwriters use static age-based tables with no clinical data. Loss ratios exceed 80% across the region.

Fraud Leakage

Manual review catches less than 30% of fraudulent claims. Billions lost to undetected anomalies annually.

Reserve Delays

Actuaries calculate IBNR reserves quarterly in spreadsheets — creating regulatory non-compliance risk.

Policy Opacity

Agents answer policyholder questions by manually searching PDFs — slow, inconsistent, and error-prone.

Siloed Systems

Each workflow runs independently. No shared risk signal. No unified view of a policyholder's true exposure.

The Result

Mispriced risk pools · Fraud leakage · Delayed reserves · Regulatory penalties · Underserved policyholders.

Section 03

The Solution — 5 Engines, 1 Platform

AfyaRisk 2.0 replaces five siloed workflows with one unified API platform. The outputs of each engine feed the next:

01

Clinical Risk Scoring Random Forest

Patient biomarkers (glucose, BMI, age, blood pressure, insulin) → Low / Medium / High risk tier + 3-year survival probability + health degradation estimate.

02

Dynamic Policy Pricing Actuarial Pure Premium

Risk tier + score → Premium = (Frequency × Severity) / (1 − Loss Ratio − Expense Loading). Risk multipliers: Low 1.0×, Medium 1.5×, High 2.5×.

03

Fraud Detection Isolation Forest

Claim features → 0–100% fraud score + explainable rule-based flags (HIGH_CLAIM_AMOUNT, RAPID_RESUBMISSION, EARLY_POLICY_LARGE_CLAIM) → APPROVE / REVIEW / REJECT.

04

IBNR Loss Reserving Chain-Ladder

Historical claims development triangle → age-to-age factors → projected ultimate losses → IBNR reserve requirement per accident year.

05

Policy RAG Search FAISS + Sentence Transformers

Natural language query → all-MiniLM-L6-v2 embedding → FAISS cosine similarity search → top-K matched policy clauses with similarity scores.

Section 04

Methodology

ML Training

All models trained on synthetic data generated at server startup — no external dataset required. 1,200 biomarker samples guarantee all 3 risk classes with minimum 50 samples each.

Actuarial Formula

Pure premium methodology with configurable loss ratio (default 65%) and expense loading (default 15%). Risk-score fine-tuning applied on top of tier multiplier.

Fraud Scoring

Isolation Forest score normalized 0–1 using training data min/max. Rule-based flags applied as a second layer for explainability alongside the ML score.

Chain-Ladder

Deterministic development factors computed as weighted column ratios. Triangle projected column-by-column. IBNR = Ultimate − Latest Diagonal per accident year.

RAG Pipeline

15 policy documents embedded at server startup in a background thread via threading.Lock(). FAISS IndexFlatIP with L2-normalized vectors for cosine similarity. Zero cold-start on first query.

API Design

FastAPI with Pydantic v2 schema validation, field-level constraints, lifespan events for startup tasks, and CORS configured for the frontend origin.
